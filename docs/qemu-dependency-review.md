## Published direct dependencies

The official [QEMU UCRT64 package page](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-qemu) identifies version `11.1.3-1`, SHA-256 `72ba6064c81408a8f433859502405da7a93e012d2b9b9bcf7f66f07750882b34`, and 67 named direct dependencies. These include `qemu-common`, `qemu-guest-agent`, `qemu-image-util`, the UCRT toolchain runtime, GTK, network, graphics, compression and font packages. The package page lists two additional *optional* packages separately; do not silently include or exclude required dependencies based on which QEMU executable is desired. The package installs multiple machine emulators, not just AArch64. The page reports an installed size of 1.01 GB for QEMU itself; total closure size remains unknown.

A read-only concurrent retrieval of the 67 linked package pages on 2026-10-30 found **at least 46 additional distinct UCRT64 names one level beyond the direct list**, using exact linked names only. One direct page (`gettext`) did not provide a parseable version/license in that pass; virtual providers, constraints, repository timestamp consistency, package conflicts, the remainder of the transitive graph, the MSYS2 base environment and operating-system runtime were not resolved. Thus these counts are diagnostic lower bounds, not a reproducible closure or proof of installability. A live page is mutable, and direct lists on these pages do not capture a single authenticated frozen repository transaction.

The matching [qemu-common](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-qemu-common) page lists `11.1.3-1`, SHA-256 `c38b37fd26f4b209bda7819dee4d8c2beb701b40d6eb6d8e8cf03b903094175d`, and no direct runtime dependencies. The [qemu-guest-agent](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-qemu-guest-agent) and [qemu-image-util](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-qemu-image-util) pages list `11.1.3-1`, but carry their own dependencies; the latter listed 25 direct UCRT64 links in the read-only pass. Exact package hashes and signatures for these and every other dependency must be captured from a retained authenticated snapshot and individually verified before selection.

## Security and licensing findings

The [QEMU page](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-qemu) declares a combined GPL-2.0-or-later, LGPL-2.1-or-later, BSD-2-Clause, BSD-3-Clause and MIT license set. This is not an itemized license audit of firmware, documentation, fonts or the full dependency set. MSYS2 metadata for direct dependencies includes `custom` or non-specific license labels, e.g. [cyrus-sasl](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-cyrus-sasl), [fontconfig](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-fontconfig), and [gmp](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-gmp). Inspect exact release and archive notices and redistribution obligations; package metadata alone does not establish compatibility.

The official pages displayed advisory lists for multiple direct dependencies, including [capstone](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-capstone), [expat](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-expat), [gnutls](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-gnutls), [libssh](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-libssh), [libssh2](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-libssh2), and [zlib](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-zlib). These are scanner signals, not proven vulnerable or exploitable instances. Check each reported advisory against exact source, patches, artifact, build options and use; also consult current upstream advisories because the package-page list is not necessarily exhaustive. The package is not ready for approval merely because QEMU itself has been assessed.

Prior evidence in the environment proposal reports mathematical verification of detached signatures for QEMU and qemu-common against a key with the fingerprint published by MSYS2, but the independent signer trust chain and certifications were not established. Other dependency archives and signatures were not retrieved or verified in this review. Do not transfer the two signature results to other artifacts. The [MSYS2 keyring documentation](https://www.msys2.org/dev/keyring/) describes the maintainer/master-key trust model.

## Required completion before an approval proposal

1. Retain an authenticated UCRT64 repository snapshot and establish independently trusted signing keys; determine exact bootstrap/base packages and constraints including provider choices.
2. Resolve the complete runtime dependency graph against that snapshot without installing or executing package contents; record every exact artifact, digest, signature, license and source recipe. Include any separately required host runtime and firmware. Treat metadata parsing errors or missing packages as blockers.
3. For every artifact assess current vendor/upstream security advisories, applicability, fixes, unresolved items and compensating controls; inspect licenses and bundled notices. Preserve review evidence and recheck if versions change.
4. Review the guest image, firmware provenance, device graph and isolation separately under G-OPS, then obtain scoped G-ARCH/G-OPS approvals before setup or boot testing. Resolution, installation and execution are distinct actions.

Evidence limits: this review fetched public package metadata only. No dependency was downloaded, installed, executed, cryptographically verified or vulnerability-scanned in this pass; no complete graph, SBOM, license clearance, risk acceptance or Pi/ARM64 boot test is claimed. External metadata can change; repeat verification for the selected frozen snapshot.
