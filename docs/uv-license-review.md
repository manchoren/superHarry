## Repository SBOM limitation

GitHub's [SBOM export documentation](https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/establish-provenance-and-integrity/export-dependencies-as-sbom) describes an SPDX export of the **current repository dependency graph**. Its [dependency graph documentation](https://docs.github.com/en/code-security/concepts/supply-chain-security/supply-chain-security) says this graph derives from manifests and lockfiles. A current graph is therefore not evidence of the specific 0.13.6 ARM64 release binary, enabled features, linked native components or original build inputs; it may change independently of the release. It can only help enumerate candidates for further review. No repository SBOM was exported in this review, and no artifact-specific SBOM was identified. GitHub's [SBOM API documentation](https://docs.github.com/en/rest/dependency-graph/sboms) also notes the older synchronous endpoint is scheduled for retirement; verify the currently supported asynchronous flow and required access before any future use. An exported SBOM still needs provenance, version-specific license evidence and a demonstrable binding to the artifact before it can close this review.
