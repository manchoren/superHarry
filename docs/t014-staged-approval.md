### Proposed command, subject to explicit approvals and all preflight gates

The following exact guest POSIX shell command is proposed for a **single invocation after the account, directories, input, `/var/tmp/superharry-t014-home/empty.npmrc`, Node/npm artifact and its internal components have been reviewed and provisioned through their separate required approvals**. The `empty.npmrc` file is an empty owner-controlled regular file, not a symlink. The only intended registry is `https://registry.npmjs.org/`. `env -i` limits inherited environment variables; it is not an OS sandbox. The command writes temporary cache/logs and `package-lock.json` inside the disposable session overlay and makes outbound registry requests; do not run it on this host or before authorization.

```sh
cd /var/tmp/superharry-t014-npm-pilot && \
  env -i \
    HOME=/var/tmp/superharry-t014-home \
    PATH=/opt/superharry-t014/node-v24.22.2-linux-arm64/bin:/usr/bin:/bin \
    npm_config_userconfig=/var/tmp/superharry-t014-home/empty.npmrc \
    npm_config_globalconfig=/var/tmp/superharry-t014-home/empty.npmrc \
    npm_config_cache=/var/tmp/superharry-t014-home/cache \
    /opt/superharry-t014/node-v24.22.2-linux-arm64/bin/npm install \
      --package-lock-only --ignore-scripts --no-audit --no-fund \
      --registry=https://registry.npmjs.org/ \
      --allow-git=none --allow-directory=none --allow-file=none --allow-remote=none
```

[npm's install documentation](https://docs.npmjs.com/cli/v11/commands/npm-install/) describes lock-only mode and `ignore-scripts`, while its [configuration reference](https://docs.npmjs.com/cli/v11/using-npm/config/) documents `allow-git`, `allow-directory`, `allow-file` and `allow-remote`. Those source restrictions and npm flags are not a firewall, complete egress restriction, proof that all npm code paths are harmless or proof of output completeness. Verify each flag and interaction for the exact bundled npm `11.19.1`, including whether `allow-remote=none` affects registry-backed packages; if any option is unsupported or blocks this pilot, stop, record the error and seek a reviewed amendment rather than relax it silently. `--no-audit` prevents implicit submission to an audit endpoint in this metadata pilot; it is **not a security scan**, and mandatory vulnerability checking remains a later blocking step.

### Static review of npm `11.19.1` source (2026-10-31)

This review examines the upstream Git tag's source, not the contents of the candidate Node archive, and does not establish the archive/source correspondence or actual execution. Its conclusions narrow the proposed pilot but do not authorize it.

- The exact [npm install entry point](https://github.com/npm/cli/blob/v11.19.1/lib/commands/install.js#L14-L46) accepts `package-lock-only`, `ignore-scripts`, `allow-directory`, `allow-file`, `allow-git`, `allow-remote`, `audit` and `fund`; the [exact configuration definitions](https://github.com/npm/cli/blob/v11.19.1/workspaces/config/lib/definitions/definitions.js#L170-L238) define each allow setting with `all`, `none` and `root`, defaulting to `all`. The proposed `--no-audit` and `--no-fund` use npm's Boolean-negation syntax; no vulnerability check is supplied by this pilot.
- For a no-argument local install, [install.js](https://github.com/npm/cli/blob/v11.19.1/lib/commands/install.js#L97-L168) constructs Arborist and gates its root lifecycle loop on `!ignoreScripts`; [Arborist's reify code](https://github.com/npm/cli/blob/v11.19.1/workspaces/arborist/lib/arborist/reify.js#L282-L292) returns early from package materialization when `packageLockOnly` is enabled, and [dependency lifecycle handling](https://github.com/npm/cli/blob/v11.19.1/workspaces/arborist/lib/arborist/reify.js#L248-L273) separately checks `ignoreScripts`. This is source-level support for the intended no-lifecycle/no-install path, not proof that no network access, metadata parsing, temp/cache writes, bugs or other process execution are possible.
- In the [tagged pacote fetcher](https://github.com/npm/cli/blob/v11.19.1/node_modules/pacote/lib/fetcher.js#L437-L476), explicit `remote`, `git`, `file`, and `directory` spec types are checked against their respective allow settings, while registry `version`, `range`, `tag`, and `alias` specs use a separate registry setting. The [tagged ideal-tree builder](https://github.com/npm/cli/blob/v11.19.1/workspaces/arborist/lib/arborist/build-ideal-tree.js) also maps source types to allow settings. This supports expecting normal `name@version` manifest lookup with `--allow-remote=none`; it does **not** prove all metadata, redirects, registry endpoints or transitive paths are restricted, and exact behavior of this specific pilot remains untested.
- The npm project tracked [issue 9347](https://github.com/npm/cli/issues/9347), where `allow-remote=none` blocked registry tarball extraction in an earlier reify path; that issue is recorded closed by a fix. The cited report is evidence of a past failure mode, not proof that version `11.19.1` has that bug or that this lock-only pilot will hit it. Registry/mirror-origin edge cases require separate review. If the candidate returns `EALLOWREMOTE`, stop; do not remove the flag or substitute a mirror without a reviewed amendment.
- [Arborist's save logic](https://github.com/npm/cli/blob/v11.19.1/workspaces/arborist/lib/arborist/reify.js#L125-L152) still saves an ideal tree after metadata resolution; inspect candidate output and source markers before considering the lock complete. A successful source reading is not a runtime test or a complete dependency/security review.

The draft command's stated expected output was not disproven by this review; actual behavior, registry-origin edge cases and source-to-binary correspondence remain unverified. In particular, the text above does not justify execution or weakening the mandatory package checks. No package or tool was downloaded or executed for this source review.
