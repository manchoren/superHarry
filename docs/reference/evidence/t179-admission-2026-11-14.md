# T179 admission follow-up - 2026-11-14

The direct-route eligibility settings no longer assume a free account, absent
billing methods or preapproved models. An absent billing declaration is
distinct from an explicitly empty list; malformed declarations also reject.
Checks use local values rather than shared mutable module globals. These are
administrative declarations and do not prove the actual account, upstream,
privacy terms or zero total cost. Synthetic tests explicitly configure their
assumptions.

The external gateway admission gate remains closed. Direct Groq/OpenRouter
dispatch also remains closed by the model-specific tokenizer/framing gate.
Finishing T179 requires a selected route with verifiable upstream identity,
account and consent eligibility, complete protected-context delivery, a bound
for the exact model and full serialized framing, context capacity and output
reserve, connected to actual admission and quota reservation. Gateway fallback
must not bypass those checks. Synthetic settings or a byte count do not supply
that evidence. T229 owns durable routing and T230 cross-route budgets; broader
provider acceptance is deferred to T241 under the product-first policy.

Windows local validation: the focused routing, quota and admission selection
passed 69 tests; after adding the separate unknown-billing dispatch regression,
the tokenizer/admission module passed six tests. `python manage.py test` passed
637 tests with 11 skipped; that run started before the final test-only addition.
`manage.py check` passed and the migration dry-run reported no changes. No
live provider, VM, deployment or release acceptance is claimed.
